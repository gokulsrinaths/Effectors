# Structure-based Effector Discovery Pipeline - Complete Project Summary

## 🎯 Project Overview

**Project Name:** Structure-based Effector Discovery Pipeline  
**Type:** Research-grade web application for protein effector identification  
**Purpose:** Enable identification and classification of protein effectors through sequence search (BLAST) and structure comparison (TM-align)

This is an NSF-style cyberinfrastructure project that provides a production-ready pipeline for biological research, with **zero mocks** - all results are real and generated by actual BLAST+ and TM-align tools.

## ✨ Key Features

### 1. **Three Input Methods**

#### A. Structure Upload (PDB/CIF)
- Upload protein structure files directly
- Compares against all 470 structures in database using TM-align
- Returns top matches with TM-scores
- **Processing Time:** 8-15 minutes (first time), < 1 second (cached)

#### B. Single Sequence Input
- Paste protein sequence in text area
- Optional sequence ID
- BLAST search → Structure mapping → TM-align
- **Processing Time:** 1-5 seconds (BLAST only) or 8-15 minutes (with TM-align)

#### C. FASTA File Upload
- Upload multi-sequence FASTA files
- Batch processing of multiple sequences
- Each sequence processed independently
- **Processing Time:** Variable (depends on number of sequences)

### 2. **Processing Pipeline**

#### Structure Upload Flow:
```
PDB/CIF File → TM-align vs All 470 Structures → Classification:
  - TM-score ≥ 0.9 → "Already in database"
  - 0.6 ≤ TM-score < 0.9 → "Known structural family"
  - TM-score < 0.5 → "Novel structure"
```

#### Sequence Upload Flow:
```
Sequence → BLAST Search → 
  ├─ If hit found → Map to structure → TM-align → Classification
  └─ If no hit → "Novel sequence" → Structure prediction required
```

### 3. **Intelligent Caching**
- TM-align results cached by file hash
- Prevents redundant computations
- Instant results for repeated uploads

### 4. **Startup Validation**
- Automatic tool detection (BLAST+, WSL, TM-align)
- Database indexing verification
- Clear error messages if tools missing
- Fatal startup errors prevent runtime failures

### 5. **Status Endpoint**
- Real-time tool availability
- Database indexing status
- Structure database file count
- WSL distro information

## 🔧 Technical Implementation Details

### Backend (`backend/main.py`)

**Key Components:**

1. **Tool Detection & Validation**
   - `check_binary()`: Finds BLAST+ binaries in PATH
   - `check_wsl_available()`: Detects WSL and distro
   - `check_tmalign_via_wsl()`: Verifies TM-align via `wsl TMalign -h`
   - `validate_binaries()`: Comprehensive startup check

2. **Database Management**
   - `ensure_blast_database_indexed()`: Auto-indexes FASTA if needed
   - `get_structure_files()`: Scans structure database directory
   - Path handling: Absolute paths, Windows → WSL conversion

3. **BLAST Integration**
   - `run_blastp_search()`: Executes real BLAST+ searches
   - Timeout: 60 seconds
   - Parses XML output for hits
   - Maps sequence IDs to structure files

4. **TM-align Integration**
   - `run_tmalign()`: Executes `wsl TMalign <pdb1> <pdb2>`
   - Automatic Windows → WSL path conversion (`C:\...` → `/mnt/c/...`)
   - Timeout: 30 seconds per comparison
   - Caching: Results stored by (query_hash, target_filename)

5. **API Endpoints**

   **Core Endpoints:**
   - `POST /upload/structure` - Structure upload (original)
   - `POST /upload/sequence` - Sequence upload (original)
   - `POST /upload/multisequence` - FASTA upload (original)
   - `GET /status` - System status

   **Frontend Compatibility Endpoints:**
   - `POST /api/process/structure` - Wraps `/upload/structure`
   - `POST /api/process/sequence` - Wraps `/upload/sequence` (JSON body)
   - `POST /api/process/fasta` - Wraps `/upload/multisequence`
   - `GET /api/job/{job_id}` - Job status (placeholder)

6. **Response Models**
   - `StructureMatchResult`: Structure comparison results
   - `SequenceResult`: Sequence search results
   - `MultiSequenceResult`: Batch processing results
   - `ProcessingResult`: Frontend-compatible format
   - `ClassificationResult`: Classification with interpretation

### Frontend (`frontend/app/page.tsx`)

**Key Features:**

1. **Three-Tab Interface**
   - Structure Upload tab
   - Sequence Input tab
   - FASTA Upload tab

2. **File Handling**
   - Drag-and-drop file uploads
   - File validation (PDB/CIF/FASTA)
   - Progress indicators

3. **Error Handling**
   - Toast notifications for errors
   - Graceful error message extraction
   - Network error handling

4. **Results Display**
   - Classification results
   - TM-scores
   - Best match information
   - Interpretation messages

### Use Cases
1. **Effector Discovery:** Identify novel protein effectors
2. **Structure Classification:** Classify structures into families
3. **Sequence Analysis:** Map sequences to known structures
4. **Batch Processing:** Analyze multiple sequences efficiently

### Classification Logic
- **TM-score ≥ 0.9:** Already in database (exact or near-exact match)
- **0.6 ≤ TM-score < 0.9:** Known structural family (similar fold)
- **TM-score < 0.5:** Novel structure (different fold)
